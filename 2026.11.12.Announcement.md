# CoreDesign 10.0.0: a Security Fix and User Journey Tracking for .NET 10

Yesterday I released CoreDesign 11 for .NET 11. Today it's the .NET 10 line's turn. CoreDesign 10.0.0 fixes a security vulnerability in the 1.x packages, and it brings most of what's new in CoreDesign 11 to teams that are staying on .NET 10 for now.

If you use CoreDesign 1.x, please read the next section and upgrade.

## Security fix: CVE-2026-120006

The 1.x packages depend on Aspire 13.4.6. Microsoft published an elevation of privilege vulnerability for Aspire versions below 13.6.5 ([CVE-2026-120006](https://github.com/advisories/GHSA-f7vh-h5g3-7jrh), rated high). Because CoreDesign.Shared references Aspire, every project using CoreDesign 1.x picks up the vulnerable version.

CoreDesign 10.0.0 depends on Aspire 13.6.5, which fixes it. MessagePack also moves to 3.1.12, which fixes a moderate vulnerability (GHSA-qhrr-8q5h-9q3h).

Published packages can't be changed, so the 1.x versions will always carry the old Aspire version. If you can't upgrade CoreDesign today, add a direct reference to the fixed Aspire version. A direct reference overrides the vulnerable one that comes in through CoreDesign:

```xml
<PackageReference Include="Aspire.Hosting.AppHost" Version="13.6.5" />
```

## Why 10.0.0 and not 1.0.6

CoreDesign 11 introduced a simpler version scheme: every package shares one version number, and the major version matches the .NET version it targets. The .NET 10 line now follows it. CoreDesign 10.x is for .NET 10 and CoreDesign 11.x is for .NET 11, so you can tell from the version alone which one your project needs.

One thing to watch: NuGet shows 11.0.1 as the latest version. In a .NET 10 project, ask for 10.0.0 explicitly. Choosing 11.0.1 fails restore with NU1202.

## New for .NET 10

When I released CoreDesign 11, I promised to keep maintaining the .NET 10 packages and to look at backporting what .NET 10 can support. This release does that. Everything below already shipped in CoreDesign 11:

- **User journey tracking.** `CoreDesign.UserJourney` tags every request with the signed-in user and client IP, drops health probe noise, strips query strings, and records what each page showed. Pick a user in Application Insights and see what they viewed and clicked, in order. A workbook is included.
- **Blazor Server support.** `CoreDesign.UserJourney.Blazor` links clicks and navigation, which travel over SignalR instead of HTTP, to the signed-in user.
- **React and other single-page apps.** The npm package `@coredesign.dev/user-journey` works with 10.0.0 unchanged.
- **Settings file naming.** `AddAppSettings(o => o.SettingsName = "LOCAL")` chooses the settings file independently of the environment name, and the loaded file is logged at startup.
- **An explicit local token injection switch.** `IdentityApi:EnableLocalTokenInjection` turns local bearer token injection on or off, instead of relying only on the environment name.
- **IP address helpers.** `IPAddress.IsPrivate()` and `IsInternal()`, for exempting internal traffic from rate limiting.

## What stays on CoreDesign 11

C# 15 unions need C# 15, which needs .NET 11. CoreDesign 10.x keeps using OneOf, and `CoreDesign.Logging` still depends on it and logs OneOf results per case, exactly as before. When you move to CoreDesign 11, your OneOf code keeps compiling, so you can switch to unions one service at a time.

## One breaking change

`AddAppSettings` no longer lets its JSON files override environment variables, user secrets or command-line arguments. Before, its files were added after every other configuration source, so they won over App Service settings and Docker environment variables. Now they sit where .NET's own `appsettings` files do, and those sources win, as in any .NET app.

If you relied on a JSON value beating an environment variable, remove the environment variable. Nothing else in your code needs to change.

## Upgrade

Change every CoreDesign package reference to 10.0.0:

```
dotnet add package CoreDesign.Shared --version 10.0.0
```

Do the same for the other CoreDesign packages you use: Logging, Data, ExceptionHandling, Identity.Client, Identity.Server and SeedTool. To add user journey tracking, install `CoreDesign.UserJourney` (or `CoreDesign.UserJourney.Blazor` for Blazor Server) at 10.0.0.

## What happens to 1.x

The 1.x packages are deprecated on NuGet, and your IDE will now point you to 10.0.0. They stay on NuGet until the community has had time to move, so existing builds keep working. New fixes for .NET 10 go into 10.x.
