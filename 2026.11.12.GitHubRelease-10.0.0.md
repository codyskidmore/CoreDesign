CoreDesign 10.0.0 is the .NET 10 release of CoreDesign. It fixes a high-severity vulnerability in the Aspire dependency of the 1.x packages and moves the .NET 10 line to the shared version scheme.

It also brings the CoreDesign 11 features that .NET 10 supports to .NET 10 apps: **user journey tracking** (the new `CoreDesign.UserJourney` and `CoreDesign.UserJourney.Blazor` packages, plus the npm package for React), **settings file naming** with `SettingsName`, an explicit **local token injection** switch, and **IP address helpers**. Only C# 15 unions stay exclusive to CoreDesign 11.

> [!IMPORTANT]
> **Security fix: CVE-2026-120006 (GHSA-f7vh-h5g3-7jrh, high).** The 1.x packages depend on Aspire 13.4.6, which has an elevation of privilege vulnerability. CoreDesign 10.0.0 depends on Aspire 13.6.5, which fixes it. Every project using CoreDesign 1.x should upgrade.
>
> If you can't upgrade right away, add a direct reference to the fixed Aspire version. It overrides the vulnerable transitive version:
>
> ```xml
> <PackageReference Include="Aspire.Hosting.AppHost" Version="13.6.5" />
> ```

> [!NOTE]
> **Which version do I need?** CoreDesign 10.x targets .NET 10, and CoreDesign 11.x targets .NET 11. NuGet lists 11.0.1 as the latest version, so .NET 10 projects must reference `10.0.0` explicitly. Choosing 11.0.1 in a .NET 10 project fails restore with NU1202.

### Versioning

Every CoreDesign package now shares one version number, and the major version matches the .NET version it targets. 10.0.0 replaces the 1.x packages, which are deprecated but stay on NuGet until the community has had time to upgrade. CoreDesign 10.x is maintained alongside 11.x. Minor and patch releases never contain breaking changes.

## 🔒 Security

- Aspire packages move from 13.4.6 to 13.6.5, fixing CVE-2026-120006 (GHSA-f7vh-h5g3-7jrh, high).
- `MessagePack` moves from 3.1.8 to 3.1.12, fixing GHSA-qhrr-8q5h-9q3h (moderate).

## ✨ New (backported from CoreDesign 11)

- **CoreDesign.UserJourney** (new package): per-user activity tracking on OpenTelemetry. Tags every request with the signed-in user and client IP, drops health probes, strips query strings, records what a page showed (`Journey.Viewed`), and maps an endpoint that browser apps send page views and clicks to. Includes an Application Insights workbook.
- **CoreDesign.UserJourney.Blazor** (new package): links Blazor Server clicks and navigation, which travel over SignalR, to the signed-in user, and adds the `JourneyView` component.
- **[@coredesign.dev/user-journey](https://www.npmjs.com/package/@coredesign.dev/user-journey)** (npm) works with 10.0.0 unchanged, for React and other single-page apps.
- **`AddAppSettings(o => o.SettingsName = "LOCAL")`**: choose the settings file name independently of the environment name, also through the `AppSettings:Name` configuration value. The loaded file is logged at startup.
- **`IdentityApi:EnableLocalTokenInjection`**: an explicit switch for local bearer token injection, instead of relying only on the environment name.
- **`IPAddress.IsPrivate()` and `IsInternal()`** in CoreDesign.Shared, for exempting internal traffic from rate limiting.

**Not backported:** C# 15 unions (`Union<...>` and `Success`) need C# 15 and .NET 11. CoreDesign 10.x keeps using OneOf, and `CoreDesign.Logging` still depends on it and logs OneOf results per case.

## ⚠️ Breaking Changes

- **`AddAppSettings` no longer overrides environment variables, user secrets or command-line arguments.** Its `appsettings` files used to be added after every other configuration source, so they won over App Service settings, Docker environment variables and user secrets. They now sit where .NET's own `appsettings` files do, so those sources override them as in any .NET app. If you relied on a JSON value beating an environment variable, remove the environment variable.
- **`CoreDesign.Identity.Client` requires `Microsoft.OpenApi` 2.13.0 or later** (required by `Microsoft.AspNetCore.OpenApi` 10.0.15). Projects that pin an older 2.x version fail restore with NU1605 until they update the pin.

## 📦 Dependency Updates

- Microsoft ASP.NET Core, EF Core and `Microsoft.Extensions.*` packages move from 10.0.10 to 10.0.15.
- `Microsoft.OpenApi` moves from 2.7.5 to 2.13.0.
- `System.IdentityModel.Tokens.Jwt` moves from 8.19.2 to 8.23.0.
- `CoreDesign.Shared` replaces a stray assembly reference to a .NET 9 `Microsoft.Extensions.Hosting.Abstractions` with the 10.0.15 package.
- `CoreDesign.Logging` drops a leftover package reference to `CoreDesign.Shared` 1.0.3 and depends on the matching CoreDesign.Shared release.

## ⬆️ Upgrading from 1.x

Change every CoreDesign package reference to `10.0.0`. No code changes are needed unless you depended on `AddAppSettings` files overriding environment variables (see Breaking Changes). When you're ready for .NET 11, see the [CoreDesign 11 upgrade guide](https://github.com/codyskidmore/CoreDesign/blob/main/CoreDesign.NET11-migration.md).
