# CoreDesign 10.0.1 is out

I shipped a patch release of CoreDesign for .NET 10 today. It's a small one, but it fixes two bugs worth knowing about if you use the logging or exception handling packages.

**Generic repositories no longer crash the logging setup.** CoreDesign.Logging generates logging decorators at compile time for any interface you mark with an attribute, including generic ones like a repository of T. The usual way to register a generic repository in ASP.NET Core is an "open generic" registration, one line that covers every entity type. In 10.0.0 that combination crashed the app at startup. In 10.0.1 those registrations are decorated properly, so every repository gets its logging with no extra code.

**Bad input gets a 400, not a 500.** CoreDesign.ExceptionHandling turns unexpected exceptions into clean, consistent error responses. It was a little too eager: when a request carried a value that couldn't be parsed, such as a malformed ID in the URL, the client got a 500 Internal Server Error. That tells the caller the server broke when really the request was wrong. Now those requests get a proper 400 Bad Request.

**One thing to check before upgrading:** the source generators now need a current .NET SDK (10.0.404 includes the required compiler). If your build machine runs an older SDK, update it first.

**The sample app runs on the new packages.** CoreDesign ships with a full sample application: an API, Blazor and React front ends, an identity server, and PostgreSQL, all orchestrated by .NET Aspire. It now runs on 10.0.1, and I verified it end to end before this release.

There are no breaking changes. Upgrading is a version number change.

Packages are on NuGet now, and the source is on GitHub: https://github.com/codyskidmore/CoreDesign
